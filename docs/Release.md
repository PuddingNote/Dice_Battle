# 구글 플레이 업로드 & 비공개 테스트 계획

> **작성일 2026-07-29 기준.** 구글의 정책 수치(Target API 레벨, 테스터 인원·기간)는 자주 바뀐다.
> 아래 숫자는 참고값이며, **작업 직전 Play Console의 현재 안내를 직접 확인**할 것.

---

## 0. 전제

- 플레이 콘솔 계정은 **이미 있음**
- 개인 개발자 계정이라 프로덕션 출시 전 **비공개 테스트 14일** 필요
- **광고는 이번 범위가 아님.** 비공개 테스트를 먼저 올리고 그 기간에 붙인다 → [Monetization.md](Monetization.md)
- 게임은 미완성이어도 됨. **테스트 14일 시계를 먼저 돌리는 것이 목표**

핵심 판단:

> 비공개 테스트 기간 중 새 빌드를 올려도 **14일 카운트는 초기화되지 않는다.**
> 그러므로 "완성 후 업로드"가 아니라 "업로드 후 완성"이 맞다.

## 2. 키스토어 (가장 먼저)

**키스토어를 잃어버리면 그 앱은 영원히 업데이트할 수 없다.** 다른 어떤 실수보다 치명적이다.

### 만들기

Unity → **Player Settings → Publishing Settings → Keystore Manager → Create New**

- 저장 위치는 **프로젝트 폴더 바깥**에 둘 것 (실수로 커밋되는 사고 방지)
- 유효기간은 기본값(25년 이상)으로
- 키스토어 비밀번호 / 별칭(alias) / 별칭 비밀번호 세 가지를 비밀번호 관리자에 기록

만든 뒤 같은 화면에서 **Custom Keystore 체크 + 방금 만든 키스토어 선택 + 비밀번호 입력**까지 해야
빌드에 실제로 적용된다. (지금은 `androidUseCustomKeystore: 0` 상태다.)

### 백업

키스토어 파일 자체를 **최소 2곳**에 백업한다. 클라우드 드라이브 + 외장 저장소 등.
비밀번호를 잃어버려도 똑같이 끝장이므로 함께 보관한다.

### git 보호

`.gitignore`에 다음을 추가해 두었다.

```
*.keystore
*.jks
```

> `ProjectSettings.asset`에는 경로(`AndroidKeystoreName`)와 별칭(`AndroidKeyaliasName`)만 남고
> 비밀번호는 저장되지 않는다. 커밋 전 `git diff`로 한 번 확인할 것.

### Play 앱 서명

첫 업로드 시 **반드시 등록**한다. 구글이 최종 서명키를 보관하고 개발자는 업로드 키만 관리한다.
업로드 키를 분실해도 구글에 재설정을 요청할 수 있어 위 사고를 구제받는 유일한 경로다.

## 3. 빌드 설정 정리

### 3-1. Target SDK 지정

**Player Settings → Other Settings → Target API Level**

지금 `Automatic (highest installed)`이라 빌드 머신에 설치된 SDK에 따라 결과가 달라진다.
Play는 현재 **API 35(Android 15) 이상**을 요구한다(매년 8월 상향). 드롭다운에서 명시적으로 고른다.

> **API 36(Android 16) 상향이 예정돼 있다.** 마감은 Play Console에서 직접 확인할 것.
> 36부터는 **edge-to-edge 표시가 강제**되어 옵트아웃이 무시된다. 이 게임은 레터박스 +
> `androidRenderOutsideSafeArea` 구조라 큰 문제는 없을 것으로 보이나,
> **올린 뒤 최신 안드로이드 기기에서 화면 가장자리를 반드시 확인할 것.**
> 광고 작업과 섞지 말고 별도 빌드로 올린다 — 문제가 나면 원인이 갈리지 않는다.

목록에 원하는 버전이 없으면 SDK가 안 깔린 것이다.
**Unity Hub → 설치 → 톱니 → 모듈 추가**에서 Android SDK/NDK Tools를 확인하거나,
Android Studio의 SDK Manager로 해당 플랫폼을 설치한다.

### 3-2. 버전

**Player Settings → Other Settings**

- `Version` → `0.9.0` (프로덕션 때 `1.0.0`)
- `Bundle Version Code` → 업로드할 때마다 +1. **안 올리면 업로드가 거부된다**

### 3-3. 앱 아이콘

**Player Settings → Icon**. 지금 기본 Unity 로고 상태다.
적응형 아이콘(Adaptive Icon)의 전경/배경까지 넣어야 최신 안드로이드에서 깔끔하다.

### 3-4. AAB 빌드

**File → Build Settings → Android**

- **Build App Bundle (Google Play)** 체크 — Play는 APK를 받지 않는다
- Compression Method: LZ4HC (선택)
- **Build** 실행

> IL2CPP 빌드는 처음이면 10~30분 걸리고 실패하기도 쉽다.
> **업로드 마감에 쫓기기 전에 미리 한 번 성공시켜 둘 것.**

## 4. 콘솔 절차

### 4-1. 앱 만들기

앱 이름 / 기본 언어(한국어) / **앱이 아닌 게임** / 무료.
무료로 만들면 **나중에 유료로 전환할 수 없다** (인앱 결제는 무료 앱에서도 가능하므로 무료가 맞다).

### 4-2. "앱 콘텐츠" 작성 — 비공개 테스트에도 전부 필요하다

비공개 테스트라고 건너뛸 수 없다. 이걸 다 채워야 트랙 출시 버튼이 열린다.

| 항목 | 이 게임의 답 |
|---|---|
| 개인정보처리방침 URL | **필요.** 정적 페이지 하나면 됨 (GitHub Pages, Notion 공개 페이지 등) |
| 앱 액세스 권한 | 로그인 없음 → 전체 공개 |
| 광고 | **"있음"으로 미리 신고** — 나중에 붙일 거라도 미리 해두면 재작성이 없다 |
| 콘텐츠 등급(IARC) | 보드게임/캐주얼, 폭력·과금 요소 없음 → 전체 이용가 예상 |
| 타겟 고객층 | **아동 대상 아님**으로 설정 (아동 대상이면 추후 광고 정책이 크게 제한된다) |
| 데이터 안전 | 지금은 수집 없음. **광고 붙인 뒤 반드시 재작성** (광고 ID 수집) |
| 정부/금융/건강 앱 | 해당 없음 |

> 국내 게임물관리위원회 등급분류는 구글이 자체등급분류사업자라 IARC 설문으로 갈음된다. 별도 신청 불필요.

### 4-3. 스토어 등록정보

| 항목 | 규격 |
|---|---|
| 앱 아이콘 | 512×512 PNG |
| 그래픽 이미지 | 1024×500 |
| 스크린샷 | 최소 2장, **가로 방향** |
| 짧은 설명 | 80자 이내 |
| 자세한 설명 | 4000자 이내 |

### 4-4. 트랙 순서

```
내부 테스트(Internal)  →  비공개 테스트(Closed)  →  프로덕션
   즉시 반영, 무제한        14일 시계 시작           최종
```

**내부 테스트를 먼저 거칠 것.** 인원 제한이 없고 즉시 반영되며 14일 요건과 무관하다.
서명이 맞는지, 실기기에서 설치·실행되는지를 여기서 확인하고 비공개로 넘긴다.

## 5. 비공개 테스트 14일

### 요건 (변동 가능 — 콘솔에서 확인)

- 테스터 **12명 이상**
- **14일 연속** 참여 상태 유지
- 테스터는 실제 구글 계정으로 **초대 링크 옵트인 후 Play에서 설치**해야 카운트된다

### 실무 주의

- **14~15명을 확보할 것.** 중간에 한 명이 옵트아웃하면 요건이 깨진다.
- 구글 그룹스로 묶으면 인원 관리가 편하다.
- 기간 중 업데이트는 자유롭다. 오히려 여러 번 올리는 게 정상적인 흐름이다.

## 6. 일정

**D+0 = 비공개 테스트 출시일** 기준.

### D-3 ~ D+0 (업로드 준비)

- [ ] 릴리즈 키스토어 생성 + Custom Keystore 적용 + 백업
- [ ] Target SDK 명시 지정
- [ ] 버전 `0.9.0` / versionCode `1`
- [ ] 앱 아이콘 교체
- [ ] **AAB 빌드 1회 성공** (실패 대비 여유 필요)
- [ ] 개인정보처리방침 페이지 + URL
- [ ] 스토어 이미지 (아이콘 512, 그래픽 1024×500, 스크린샷 2장 이상)
- [ ] 테스터 14명 이상 섭외

### D+0 ~ D+2 (시계 켜기 — 최우선)

- [ ] 콘솔에서 앱 생성 + 앱 콘텐츠 전 항목 작성
- [ ] 스토어 등록정보 입력
- [ ] 내부 테스트 업로드 → 실기기 설치·실행 확인
- [ ] **비공개 테스트 출시 + 테스터 초대**
- [ ] 테스터 옵트인/설치 확인

> 이 시점 빌드는 광고가 없어도 되고 덜 완성돼도 된다. **크래시 없이 한 판이 끝나면 충분하다.**

### D+2 ~ D+10 (완성 — 테스트 돌아가는 중)

- [ ] 실기기 검증 (아래 7장)
- [ ] 광고 연동 → [Monetization.md](Monetization.md)
- [ ] 남은 밸런스/연출 다듬기
- [ ] 2~3일에 한 번 비공개 트랙 업데이트 (versionCode +1)

### D+10 ~ D+14 (안정화)

- [ ] 새 기능 투입 중단, 버그 수정만
- [ ] 데이터 안전 양식을 광고 반영해 최종 수정
- [ ] 버전 `1.0.0`

### D+14 이후

- [ ] 프로덕션 출시 신청
- [ ] **단계적 출시 20%로 시작** — 크래시 터지면 중단 가능
- [ ] 크래시율 확인 후 100%

## 7. 실기기에서 확인해야 할 것

에디터에서 확인이 불가능해 미검증으로 남아 있는 항목. 내부 테스트 빌드에서 가장 먼저 본다.

- **안드로이드 뒤로가기 버튼** — 에디터에서 Esc로만 확인했다. 실기기에서 `Keyboard.current`가 null이거나,
  OS가 다이얼로그보다 먼저 앱을 종료할 수 있다. 그 경우 `Application.wantsToQuit` 훅이 필요하다.
- **한글 폰트** — `Clear Dynamic Data On Build` 이후 동적 아틀라스가 빌드에서 정상 생성되는지.
  깨지면 □□□로 나온다.
- **노치/펀치홀** — `androidRenderOutsideSafeArea: 1` 상태에서 21:9 기기 표시.
- **BGM 스트리밍** — 저사양 기기에서 끊김 여부.
- **터치 반응/성능** — 특히 알까기 연출 구간의 프레임.
- **버전 확인 통신** — 실기기에서 `version.json`을 실제로 읽는지 **미확인**.
  fail-open이라 통신이 실패해도 게임은 똑같이 잘 돌아가서 화면만 봐서는 구분되지 않는다.
  강제 업데이트가 안 먹는 것 같으면 여기부터 의심할 것 → [ForceUpdate.md](ForceUpdate.md) 5장

## 8. 매 업로드 체크리스트

- [ ] `Bundle Version Code` +1
- [ ] `Version` 갱신
- [ ] 릴리즈 키스토어로 서명 (Custom Keystore 체크 상태 확인)
- [ ] AAB 형식
- [ ] 콘솔 에러 0, EditMode 테스트 통과
- [ ] 실기기 1회 플레이 확인
- [ ] **출시 완료 후** 필요하면 `version.json`의 `minVersion` 상향 → [ForceUpdate.md](ForceUpdate.md)
      (규칙·저장형식 변경, 치명적 버그 수정일 때만. **배포 전에 올리면 안 된다**)
