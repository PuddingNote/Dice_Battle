# AdMob 연동 준비 (계정 · 플러그인)

> **작성일 2026-07-31.** AdMob 콘솔과 유니티 플러그인의 **화면 문구·메뉴 위치는 자주 바뀐다.**
> 아래는 흐름이며, 이름이 조금 달라도 같은 것을 찾으면 된다.
>
> 이 문서는 **코드를 짜기 전에 해야 하는 준비**만 다룬다. 광고를 어디에 왜 넣는지는
> [Monetization.md](Monetization.md), 실제 구현은 그 뒤다.

---

## 0. 이 문서가 끝나면 손에 남는 것

```
앱 ID          ca-app-pub-0000000000000000~1111111111     (물결표 ~)
전면 광고 단위  ca-app-pub-0000000000000000/2222222222     (슬래시 /)
보상형 광고 단위 ca-app-pub-0000000000000000/3333333333     (슬래시 /)
```

**앱 ID는 `~`, 광고 단위 ID는 `/`.** 가장 흔한 실수가 이 둘을 바꿔 넣는 것이다.
앱 ID를 잘못 넣으면 **앱이 실행 즉시 크래시난다.**

## 1. AdMob 콘솔 — 앱 등록

[apps.admob.com](https://apps.admob.com) → **앱 → 앱 추가**

### 1-1. 플랫폼

**Android** 선택.

### 1-2. "지원되는 앱 스토어에 등록되어 있나요?"

비공개 테스트 중인 앱은 **스토어 검색에 잡히지 않는다.** 그러니 여기서는 **아니오**를 고르고
앱 이름을 직접 입력한다(`다이스 배틀`).

> 프로덕션 출시 후 AdMob에서 **앱 → 앱 설정 → 앱 스토어에 연결**로 나중에 붙일 수 있다.
> 연결해두면 스토어 정보 기반으로 광고 매칭이 개선되므로, **출시 후에 반드시 연결할 것.**

### 1-3. 사용자 측정항목

켜도 되고 꺼도 된다. 켜면 Firebase/Google Analytics 연동을 권하는데,
**지금은 꺼두는 것을 권한다.** 데이터 안전 양식에 신고할 항목이 늘어난다.

앱을 만들면 **앱 ID**가 나온다. 복사해둔다.

## 2. AdMob 콘솔 — 광고 단위 2개

**앱 → (다이스 배틀) → 광고 단위 → 광고 단위 추가**

### 2-1. 전면 광고

| 항목 | 값 |
|---|---|
| 형식 | **전면 광고 (Interstitial)** |
| 이름 | `결과화면 전면` (콘솔에서만 보이는 이름, 아무거나) |
| 고급 설정 | 손대지 않는다 |

### 2-2. 보상형 광고

| 항목 | 값 |
|---|---|
| 형식 | **보상형 (Rewarded)** |
| 이름 | `리롤 추가` |
| 보상 항목 | `리롤` |
| 보상 수량 | `1` |

> 보상 항목·수량은 **AdMob 콘솔에 기록만 될 뿐 게임에 자동 반영되지 않는다.**
> 실제로 리롤을 주는 건 앱 코드다. 콘솔 값은 리포트 구분용이라고 생각하면 된다.

각각 **광고 단위 ID**가 나온다. 둘 다 복사해둔다.

> 새로 만든 광고 단위는 **실제 광고가 나오기까지 몇 시간 걸릴 수 있다.**
> 이건 정상이며, 개발 중에는 어차피 테스트 광고를 쓰므로 기다릴 필요가 없다.

## 3. AdMob 콘솔 — 나머지 설정

### 3-1. 지급 정보

**결제 → 결제 정보.** 수익을 실제로 받으려면 필요하다. 광고 게재 자체는 이것 없이도 된다.
(주소 확인용 PIN 우편이 오고, 일정 금액 도달 후 지급된다.)

### 3-2. 개인정보 및 메시지 (UMP) — 배포 국가에 달렸다

**개인정보 보호 및 메시지 → GDPR**

| 배포 범위 | 필요한가 |
|---|---|
| **한국만** | 필요 없음 |
| 전 세계 (기본값) | **필요함.** EU 사용자에게 동의 창을 띄우지 않으면 정책 위반 |

Play Console에서 배포 국가를 한국으로 제한하면 이 작업이 통째로 사라진다.
**첫 출시에는 한국 제한을 권한다.** 나중에 넓힐 때 UMP를 붙이면 된다.

### 3-3. app-ads.txt

콘솔에 경고가 뜰 수 있다. **개발자 웹사이트가 있어야** 설정 가능하고,
없으면 그냥 두면 된다. 수익에 약간 영향이 있으나 지금 단계에서 필수는 아니다.

### 3-4. 테스트 기기 등록 (나중에 유용)

**설정 → 테스트 기기.** 실제 광고 단위 ID로 바꾼 뒤 내 폰에서 확인할 때,
이걸 등록해두면 **실제 광고 대신 테스트 광고가 나와 계정이 안전하다.**
7단계(실제 ID 교체)에서 다시 볼 것.

## 4. 유니티 — 플러그인 설치

### 4-1. 내려받기

[github.com/googleads/googleads-mobile-unity/releases](https://github.com/googleads/googleads-mobile-unity/releases)

최신 릴리스의 **`GoogleMobileAds-vX.X.X.unitypackage`** 를 받는다.

### 4-2. 임포트

유니티를 열고 **Assets → Import Package → Custom Package** → 받은 파일 선택 → **Import**(전체).

같이 들어오는 것:

- `Assets/GoogleMobileAds/` — 플러그인 본체
- `Assets/ExternalDependencyManager/` — **EDM4U.** 안드로이드 라이브러리를 Gradle에 자동으로 물려주는 도구다. 빼면 안 된다.

임포트 후 **"Android Resolver를 활성화할까요?"** 류의 창이 뜨면 **Enable / Yes.**

### 4-3. 앱 ID 입력 — 빠뜨리면 앱이 크래시난다

**Assets → Google Mobile Ads → Settings**

| 칸 | 넣을 값 |
|---|---|
| **Android App ID** | 1단계에서 받은 **앱 ID** (`~` 들어간 것) |
| iOS App ID | 비워둔다 |

> **개발 중에도 여기는 실제 앱 ID를 넣는다.** 계정이 위험해지는 건 *광고 단위 ID*를
> 실제 것으로 쓰고 광고를 눌렀을 때다. 앱 ID는 매니페스트 식별용이라 무관하다.
>
> 이 값이 비어 있거나 형식이 틀리면 **안드로이드에서 실행 즉시 크래시난다.**
> 광고 코드를 한 줄도 안 불렀어도 그렇다 — SDK가 시작 시점에 매니페스트를 읽기 때문이다.

### 4-4. 의존성 해결

**Assets → External Dependency Manager → Android Resolver → Force Resolve**

`Assets/Plugins/Android/`에 `.aar` 파일들이 생기면 성공이다. 몇 분 걸린다.

## 5. 설치 확인 (코드 없이)

여기까지 하고 **광고 코드를 한 줄도 안 짠 상태로** 확인한다.

- [ ] 유니티 콘솔에 컴파일 에러 0
- [ ] `Assets/Plugins/Android/`에 `.aar` 파일들이 생성됨
- [ ] **AAB 빌드가 성공**한다
- [ ] 실기기에 설치해 실행 — **크래시 없이 메인 메뉴가 뜬다**

> 마지막 항목이 핵심이다. 광고 SDK는 앱을 실행하는 것만으로도 크래시를 낼 수 있어서
> (앱 ID 오류, Gradle 충돌), **광고 코드를 얹기 전에 "설치만 해도 멀쩡한지"를 먼저 못 박는다.**
> 나중에 문제가 생겼을 때 SDK 탓인지 내 코드 탓인지 구분할 수 있게 된다.

빌드가 실패하면 대부분 Gradle 의존성 충돌이다. Force Resolve를 다시 하거나,
`Assets/Plugins/Android/`를 지우고 Force Resolve를 다시 돌린다.

## 6. 테스트 광고 ID (구현 단계에서 씀)

구글이 공개한 **누구나 쓸 수 있는** 테스트용 ID다. 개발 내내 이것만 쓴다.

```
Android 전면   ca-app-pub-3940256099942544/1033173712
Android 보상형 ca-app-pub-3940256099942544/5224354917
```

> 값은 [구글 공식 문서](https://developers.google.com/admob/unity/test-ads)에서 한 번 확인할 것.
>
> **실제 광고 단위 ID로 개발 중 테스트하면 계정이 정지될 수 있다.** 내가 내 광고를 반복
> 클릭하는 것은 무효 트래픽이고, AdMob은 이걸 자동으로 잡아낸다. 정지되면 되돌리기 어렵다.

## 7-1. 간헐적으로 광고 화면이 멈춘다 (2026-08-10)

**증상.** 실기기에서 광고를 보면 어쩔 땐 정상인데, 어쩔 땐 "테스트 광고" 표시만 뜬 화면에
아무것도 안 나오고 **닫기 버튼도 없어 앱을 강제 종료해야만 빠져나올 수 있다.** 항상
재현되지는 않는다.

**접어둔 이론들.** 순서대로 의심했다가 증거로 하나씩 빠졌다.

1. **광고 만료(1시간)** — 만료 처리(50분 재로드 + 60초 주기 갱신)를 넣어 뒀지만,
   실제 `adb logcat`으로 잡은 첫 재현은 **앱 실행 79초 만에, 그 세션의 첫 번째 광고**에서
   일어났다. 방치와 무관했다.
2. **반복 호출 사이의 경합**(표시 중인 광고를 `Destroy()`하거나, 닫히자마자 같은 프레임에서
   다음 광고를 로드하는 것) — 코드상 있던 진짜 구멍이라 고쳤지만, 위와 같은 이유로
   **이 재현 사례의 직접 원인은 아니었다.** 세 번째 호출도 없이 첫 광고에서 걸렸다.
3. **기기의 낡은 WebView/Play 서비스** — 확인해 보니 이미 최신이었다.
4. **SDK 내부 타임아웃을 못 기다린 것** — 5분 넘게 기다려도 복구되지 않았다.

**logcat이 실제로 보여준 것.** 광고 창(`AdActivity`)은 만들어지지만 내용이 끝까지
그려지지 않는다 — 크래시도 ANR도 에러 로그도 없이, `mDrawState=DRAW_PENDING`에서
그대로 멈춘다. 이 자체가 원인이 아니라 **증상**이다. 진짜 문제는 그 다음이었다:

- **Legacy Android SDK**에서는 이 렌더링 실패가 일어나면 실패 콜백이 오지 않았다.
  5분을 기다려도 그대로였다.
- 앱은 `runInBackground: 0`이라 광고가 포커스를 가져간 동안 **유니티 스크립트 실행이
  통째로 멈춘다.** 그래서 앱 쪽 워치독 코드도 이 시간에는 아예 돌 수 없다.
- 두 가지가 겹치면 빠져나올 방법이 없다 — 네이티브 SDK도 안 끝내주고, 앱 코드도 못 끼어든다.

**해결: GMA Next-Gen Android SDK로 전환.**
`Assets → Google Mobile Ads → Settings → Switch Google Mobile Ads Android architecture` 체크
→ `Upgrade to the GMA Next-Gen SDK` 선택.

같은 렌더링 실패는 이후에도 재현됐다(첫 시도가 다시 안 그려짐) — **이 스위치가 실패
자체를 없애지는 못한다.** 대신 logcat으로 확인한 차이가 이거다: Next-Gen SDK는 그 실패를
스스로 감지해 **8초 만에 액티비티를 정상적으로 `finish()`** 하고 포커스를 게임으로
돌려줬다. 그래서 앱의 실패 콜백(`OnAdFullScreenContentFailed`)이 제때 도착했고,
이미 만들어 둔 "광고를 불러오지 못했습니다. 잠시 후 다시 시도해 주세요" 안내로 정상
복구됐다. 두 번째 시도는 15.6초간 유지되다 닫혀 실제로 끝까지 재생됐다.

> **가끔 광고 로딩이 실패하는 것 자체는 정상이다.** 모든 광고 SDK가 겪는 일이고, 실패
> 콜백만 제때 오면 게임은 이미 그 경우를 정상 처리하도록 되어 있었다. 문제였던 건
> "실패했을 때 빠져나올 방법이 없었다"는 것이지 "가끔 실패한다"가 아니다.

**같이 고친 것(코드).** 원인의 직접 증거는 아니지만 방어로 남겨 둔다 — 순서 2번의 경합은
실제로 있던 버그였고, SDK를 바꿔도 무해하다.

- 표시 중인 광고는 다시 싣지 않는다(파괴 방지).
- 광고가 닫힌 뒤 다음 로드를 한 프레임 이상 늦춘다(`ReloadAfterClose`).
- 앱으로 돌아왔는데 표시 중 상태가 안 풀리면 1.5초 뒤 강제로 정리한다(콜백 유실 복구).
  광고가 화면을 실제로 가져갔던 경우에만 발동한다 — `Show()` 직후 포커스가 한 번 튀는
  것만 보고 판단하면 멀쩡히 재생 중인 광고를 끊는다.
- 50분 만료 처리 + 60초 주기 갱신 — 오래 방치한 경우의 방어선.

> **이 방어 코드들은 `runInBackground: 0`인 동안은 애초에 실행되지 않는다.** 광고가
> 포커스를 가진 시간에는 무력하다. 실제로 문제를 풀어낸 건 SDK 전환이다.
