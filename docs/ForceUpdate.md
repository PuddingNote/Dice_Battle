# 강제 업데이트 운영

> **작성일 2026-07-31.** 구현은 끝났고, 이 문서는 **매 업데이트마다 뭘 해야 하는지**를 다룬다.
> 이 기능은 코드보다 **순서를 틀리는 쪽이 훨씬 위험하다.** 3장을 반드시 읽을 것.

---

## 1. 무엇을 해결하는가

플레이스토어 자동 업데이트를 꺼둔 사용자가 많다. 새 버전을 올려도 **본인이 직접 스토어에
들어가 보지 않으면 업데이트가 나온 줄도 모르고** 구버전을 계속 쓴다.

그래서 앱이 실행 직후 스스로 확인하고, 구버전이면 닫을 수 없는 창으로 막은 뒤
스토어로 보낸다.

---

## 2. 구조

```
GameBootstrap
  └ VersionGate            실행 직후 원격 JSON 조회 → 버전 비교
       └ UpdateRequiredView  닫을 수 없는 차단 창 [종료] [업데이트]

AppVersion (Core)          "0.10.0" > "0.9.9" 를 보장하는 숫자 비교
```

| 파일 | 역할 |
|---|---|
| `Assets/Scripts/Core/AppVersion.cs` | 버전 문자열 비교(순수 C#, 테스트 6건) |
| `Assets/Scripts/UI/VersionGate.cs` | 원격 조회·판정. **URL이 여기 상수로 박혀 있다** |
| `Assets/Scripts/UI/UpdateRequiredView.cs` | 차단 창 UI |
| `version.json` | 운영 중 실제로 바꾸는 파일. **2026-08-11부터 이 저장소가 아니라 `PuddingNote.github.io/dicebattle/version.json`을 고친다** — 아래 참고 |

읽는 주소:

```
https://puddingnote.github.io/dicebattle/version.json
```

**2026-08-11: 저장소를 옮겼다.** 게임 저장소들을 이후 private으로 바꿀 예정이라,
개인정보처리방침과 함께 별도의 공개 저장소(`PuddingNote.github.io`, 게임별 폴더)로
`version.json`을 옮겼다. 예전 주소
(`raw.githubusercontent.com/PuddingNote/Dice_Battle/master/version.json`)는
**이 URL로 바뀐 새 빌드가 Play에 충분히 퍼질 때까지 지우면 안 된다** — 그 전에
지우면 아직 구버전을 쓰는 사용자의 강제 업데이트 확인이 조용히 무력화된다
(fail-open 설계라 게임이 막히진 않지만, 확인 자체가 안 된다). 이 저장소의
`version.json`(루트)과 `docs/privacy-policy.html`은 안전하다고 판단되면 삭제
예정 — 그때까지는 남겨 둔다.

### version.json 형식

```json
{
  "minVersion": "0.0.0",
  "storeUrl": "https://play.google.com/store/apps/details?id=com.onepixel.dicebattle",
  "message": "새로운 버전이 나왔습니다.\n업데이트 후 이용해 주세요."
}
```

| 키 | 설명 |
|---|---|
| `minVersion` | **이 버전보다 낮으면 차단.** 비어 있거나 깨져 있으면 아무도 막지 않는다 |
| `storeUrl` | [업데이트] 버튼이 여는 주소. 비우면 패키지명으로 자동 생성 |
| `message` | 차단 창 문구. 비우면 기본 문구. `\n`으로 줄바꿈 |

**세 값 모두 앱 재빌드 없이 바꿀 수 있다.** 문구만 고치고 싶을 때도 빌드가 필요 없다.

## 3. 운영 순서 (중요)

### 반드시 이 순서

```
1. 새 버전 빌드 → Play 업로드
2. Play에서 "출시 완료" 상태 확인          ← 여기를 기다린다
3. version.json 의 minVersion 을 올린다
4. 푸시
```

### 왜 3번이 2번 뒤인가

**minVersion을 먼저 올리면 사용자는 게임도 못 하고 받을 업데이트도 없는 상태가 된다.**
차단 창이 뜨고, [업데이트]를 눌러 스토어에 가면 여전히 구버전만 있어서 할 수 있는 게 없다.
이 상태는 사용자가 앱을 지우게 만든다.

Play는 업로드 후 검토·배포에 시간이 걸리고, 단계적 출시를 쓰면 일부 사용자에게만 먼저 간다.
**단계적 출시 중에는 minVersion을 올리면 안 된다.** 아직 새 버전을 받을 수 없는 사용자가 남아 있다.

### 언제 올려야 하는가

`minVersion`은 **매번 올리는 값이 아니다.** 올려야 하는 경우만:

| 상황 | minVersion |
|---|---|
| 게임 규칙·밸런스가 바뀜 | **올린다** |
| 저장 데이터 형식이 바뀜 | **올린다** |
| 크래시·치명적 버그 수정 | **올린다** |
| 광고 SDK 도입·교체 | **올린다** |
| UI 다듬기, 문구 수정, 연출 개선 | 올리지 않는다 |
| 새 기능 추가(구버전도 정상 동작) | 올리지 않는다 |

사소한 변경까지 강제하면 사용자는 게임을 켤 때마다 업데이트 화면을 보게 되고, 그게 곧 이탈이다.

### 반영 시간

`raw.githubusercontent.com`은 CDN 캐시가 있어 **푸시 후 반영까지 1~5분** 걸린다.
위 순서대로라면 급할 일이 없으므로 문제가 되지 않는다.

## 4. 안전장치 (일부러 이렇게 만들었다)

**확인에 실패하면 통과시킨다(fail-open).** 아래는 전부 "그냥 통과"로 처리된다.

- 오프라인 / 비행기 모드 / 지하철
- 깃허브 장애, 404, 타임아웃(5초)
- `version.json` JSON 문법 오류
- `minVersion`이 비었거나 숫자가 아님

오타 하나로 **전체 사용자가 게임을 못 켜는** 사고가, 일부가 구버전을 쓰는 것보다 훨씬 나쁘기 때문이다.
바꿔 말하면 **차단이 안 걸려도 조용히 넘어간다.** 강제가 먹었는지 확인하려면 실제로 확인해봐야 한다(6장).

**뒤로가기는 종료로만 동작한다.** 이걸 막지 않으면 뒤로가기로 연 확인 다이얼로그가
차단 창 **위로** 올라와 그 틈으로 게임에 들어갈 수 있다. (`GameManager.OnBackPressed`)

**스토어로 보낸 뒤에도 창을 닫지 않는다.** 업데이트하지 않고 앱으로 돌아와도 여전히 막혀 있어야 한다.

---

## 5. 사고가 났을 때

**전원이 차단됐다** → `version.json`의 `minVersion`을 `"0.0.0"`으로 되돌리고 푸시.
앱 재빌드도 스토어 업로드도 필요 없다. 1~5분 뒤 정상화된다. **이게 원격 파일로 만든 이유다.**

**차단이 안 걸린다** → 순서대로 확인:
1. 위 URL이 브라우저에서 열리는가
2. `minVersion`이 설치된 버전보다 **높은가**
3. 콘솔/logcat에 `[VersionGate]` 로그가 무엇으로 찍히는가
4. **Player Settings → Other Settings → Internet Access 가 `Require`인가**
   (`Auto`는 IL2CPP 스트리핑에서 판단이 빗나갈 수 있고, 그러면 실기기에서만 조용히 실패한다)

---

## 6. 확인 방법

1. `version.json`의 `minVersion`을 설치된 버전보다 높게(예: `"9.9.9"`) 바꿔 푸시
2. 1~2분 뒤 실행
3. 차단 창이 뜨는지, 뒤로가기로 빠져나갈 수 없는지, [업데이트]가 Play 페이지를 여는지 확인
4. **`"0.0.0"`으로 되돌린다**

> 4번을 잊고 새 빌드를 올리면 그 빌드도 똑같이 막힌다.

비공개 테스트 중에는 **옵트인한 테스터 계정에서만** Play 페이지가 보인다.
초대받지 않은 계정에서 "찾을 수 없는 페이지"가 나오는 것은 정상이다.
