# 광고 / 수익 모델 설계

> **작성일 2026-07-29 / 갱신 2026-07-31.**
> 설계 문서다. 아래 6장에 구현 진행 상황이 표시되어 있다.
> 계정·플러그인 준비 절차는 [AdMobSetup.md](AdMobSetup.md).
>
> **확정된 수치** (설계 당시 범위로만 적었던 것들):
> 전면 광고는 **3판마다 1회, 최소 간격 90초**. 보상형 리롤은 **판당 1회**이며
> 버튼을 누르면 바로 재생하지 않고 **확인 창을 먼저** 띄운다.
> 인앱 결제는 여전히 넣지 않는다.

---

## 1. 방향

첫 출시에서는 **광고만** 넣고 인앱 결제는 넣지 않는다.

이유:

- 인앱 결제는 콘솔 설정(상품 등록, 결제 프로필, 세금 정보)이 추가로 붙어 일정이 늘어난다.
- 이 게임은 **운이 지배적인 짧은 판 구조**라 밸런스를 파는 상품(강한 주사위 등)을 만들면 게임이 망가진다.
- 수익화보다 먼저 **사람이 계속 하는지**를 확인해야 한다.

인앱 결제는 v1.1 이후 **"광고 제거" 단일 상품**으로 시작하는 것이 자연스럽다.
광고를 먼저 붙여둬야 "제거" 상품이 성립한다는 점에서도 순서가 맞다.

## 2. 광고 종류별 판단

### 2-1. 전면 광고 (Interstitial) — **넣는다**

한 판이 끝나고 결과 화면에서 나갈 때 노출한다.

- **노출 지점**: 결과 창의 `다시 하기` / `메뉴로`를 눌러 화면이 전환되는 순간
- **빈도**: 2~3판에 1회. 매 판마다는 이탈을 부른다
- **금지 규칙**
  - 첫 실행 첫 판은 노출하지 않는다 (첫인상)
  - 연속 노출 금지 (최소 간격 60~90초)
  - **판이 진행되는 도중에는 절대 노출하지 않는다** — 정책 위반이자 최악의 경험

> 결과 화면 전환은 구글이 권장하는 "자연스러운 전환 지점"에 해당한다.
> 반대로 게임 시작 버튼을 누른 직후 노출하는 것은 사용자가 의도한 행동을 가로막는 형태라 피한다.

### 2-2. 보상형 광고 (Rewarded) — **넣는다. 여기가 핵심**

강제가 아니라 **사용자가 원해서 보는** 광고다. eCPM도 가장 높고 정책 위험도 가장 낮다.

이 게임에 맞는 보상은 두 가지다.

**A. 리롤 1회 추가**

이미 판당 1회 리롤이 있다. 소진한 뒤 리롤 버튼을 누르면
"광고를 보고 1회 더 굴리시겠습니까?"를 띄운다.

- 기존 UI/규칙에 자연스럽게 얹힌다 — 새 개념을 만들 필요가 없다
- 운이 지배적인 게임이라 "한 번 더 굴리고 싶다"는 욕구가 실제로 생긴다
- 밸런스 영향이 제한적이다 (주사위를 유리하게 바꾸는 게 아니라 한 번 더 굴릴 뿐)

**B. 패배 시 점수 방어**

패배하면 -10점인데, 광고를 보면 점수 하락을 취소한다.

- 등급 시스템이 있어 점수에 대한 애착이 이미 만들어져 있다
- 등급 강등 직전(예: 100점에서 패배해 Lv2→Lv1)에 특히 강하게 작동한다
- 결과 화면에 "점수 지키기 (광고)" 버튼 형태

**둘 다 넣되 A부터 구현**한다. A가 게임 중 자연스럽고, B는 결과 화면 UI 변경이 더 크다.

### 2-3. 배너 — **넣지 않는다**

이 게임의 레이아웃과 정면으로 충돌한다.

현재 화면은 `LetterboxScaler`로 1920×1080을 균등 스케일하고, **하단에 주사위 트레이와 리롤 버튼**이 붙어 있다.
16:9 기기에서는 레터박스 여백이 없어 배너가 트레이나 리롤 버튼을 그대로 덮는다.
세로로 긴 기기에서는 여백이 생기지만, 기기마다 배너 위치가 달라져 일관성이 깨진다.

**오조작으로 인한 광고 클릭은 정책 위반 소지도 있다.** 배너 수익은 전면·보상형에 비해 미미하므로 포기한다.

### 2-4. 앱 오프닝 광고 (App Open) — **넣지 않는다**

앱 실행/복귀 시 전체 화면 광고. 수익은 되지만 잘못 쓰면 정책 위반으로 계정에 문제가 생기기 쉽다.
첫 출시에서 감수할 위험이 아니다.

## 3. SDK 선택

| | Google AdMob | Unity Ads (LevelPlay) |
|---|---|---|
| 연동 | 외부 Unity 플러그인 설치 | Package Manager |
| 국내 수익 | 일반적으로 더 높음 | 보통 |
| 초기 세팅 | 다소 복잡 | 간단 |
| 확장 | 미디에이션으로 Unity Ads 포함 가능 | LevelPlay 미디에이션 |

**AdMob을 권장한다.** 초기 세팅이 조금 더 걸리지만 수익 차이가 있고, 나중에 미디에이션으로 확장할 때 중심이 된다.
다만 **2주 일정이 빡빡하다고 판단되면 Unity Ads로 먼저 붙이는 것도 합리적**이다. 나중에 교체 가능하도록
아래 구조를 지키면 SDK 교체 비용이 낮아진다.

## 4. 코드 구조 (이 프로젝트에 맞춘 설계)

`AudioManager`와 같은 패턴을 따른다. **SDK 호출을 한 클래스에 가두어** 나중에 교체할 수 있게 한다.

```
GameBootstrap
  └ AdManager (MonoBehaviour, 정적 접근)
       ├ Initialize()          SDK 초기화, 광고 미리 로드
       ├ ShowInterstitial()    조건(빈도/간격) 검사 후 노출
       ├ ShowRewarded(Action onReward)   보상형, 성공 시에만 콜백
       └ IsRewardedReady
```

- SDK 타입은 `AdManager` 밖으로 새어 나가지 않게 한다
- 광고가 없거나 로드 실패해도 **게임은 정상 진행**되어야 한다 (`AudioManager`가 클립 없을 때 무음으로 넘어가듯)
- 에디터에서는 항상 "광고 없음"으로 동작하게 해서 개발 흐름을 막지 않는다

### 연동 지점

| 위치 | 파일 | 내용 |
|---|---|---|
| 전면 광고 | `GameManager.OnMatchFinished` 또는 결과 화면 버튼 | 판 종료 후 화면 전환 시 |
| 보상형 (리롤) | `GameController.OnRerollClicked` | `_rerollAvailable == false`일 때 광고 제안 |
| 보상형 (점수 방어) | `GameManager.OnMatchFinished` | 패배 시 결과 화면에 버튼 추가 |
| UI | `ConfirmDialogView` 재활용 | "광고를 보고 리롤 1회 더?" 확인 창 |

### 반드시 처리해야 하는 것

**BGM 처리** — 광고는 오디오 포커스를 가져간다. 광고 표시 전 BGM을 멈추고 닫힌 뒤 재개해야 한다.
`AudioManager`에 일시정지/재개를 추가한다. 지금은 ON/OFF만 있다.

**게임 진행 정지** — 광고 중에도 AI 턴 코루틴은 계속 돈다. 결과 화면에서만 전면 광고를 띄우면
큰 문제는 없지만, 보상형(리롤)은 판 진행 중이라 **광고 시간 동안 게임이 멈춰야 한다.**
`Time.timeScale = 0` 또는 명시적 일시정지가 필요하다.

**보상 지급 시점** — 광고를 끝까지 본 콜백에서만 보상을 준다. 중간에 닫으면 주지 않는다.
네트워크 실패로 광고가 안 뜨면 **보상을 주지 않되 사용자에게 명확히 알린다.**

## 5. 정책·서류 연동 (중요)

광고를 넣는 순간 [Release.md](Release.md)의 서류 내용이 바뀐다.

- **앱 콘텐츠 → 광고: "있음"** 으로 신고. 나중에 넣을 거라도 미리 신고해두면 재작성이 없다.
- **데이터 안전 양식** — 게임 자체는 아무것도 수집하지 않지만 **광고 SDK가 광고 ID와 기기 정보를 수집**한다.
  "수집 안 함"으로 신고해두면 나중에 위반이 된다.
- **개인정보처리방침**에 광고 식별자 수집 및 제3자(구글) 제공 문구가 들어가야 한다.
- **광고 ID 권한** — Android 13 이상에서 `AD_ID` 권한 선언이 필요하다. 보통 SDK가 자동으로 추가한다.
- **타겟 고객층을 아동 대상으로 설정하지 않는다.** 아동 대상이 되면 광고 정책이 크게 제한된다.
- **동의 수집(UMP)** — Play는 전 세계 배포가 기본이라 EU 사용자를 만나게 된다.
  AdMob의 UMP(User Messaging Platform)로 동의 창을 붙이거나, **배포 국가를 한국으로 제한**한다.
  초기에는 국가 제한이 단순하다.

3. ~~전면 광고: 결과 화면 전환 지점 (빈도 제한 포함)~~ **완료**
4. ~~`AudioManager` BGM 일시정지/재개 추가~~ **완료**
5. ~~보상형 A: 리롤 1회 추가 (게임 일시정지 포함)~~ **완료**
6. 보상형 B: 패배 시 점수 방어 — **v1.1로 미룸**
7. 실제 광고 ID 교체 + 실기기 검증 ← **다음**
8. 데이터 안전 / 개인정보처리방침 최종 수정

7번 전에 **실기기에서 테스트 광고로 전체 흐름을 먼저 확인**한다.
에디터에서도 `AdManager.EnableInEditor`가 켜져 있으면 회색 자리표시 광고로 흐름을 볼 수 있으나,
BGM 정지/재개나 오디오 포커스처럼 **실기기에서만 드러나는 문제는 걸러지지 않는다.**
